# Known limitations

Written to be read by someone deciding whether to trust a number in
`docs/results.md`. Ordered by how much they should change your reading.

---

## 1. The target is simulated. No LLM is called.

`SimulatedAgent` is a compliance function: a base probability modified by
channel, forged authority, and payload legibility, resolved against a hash of
the attack id. It is not a language model and it does not pretend to be.

This constrains the results **asymmetrically**, which is why the report is
built the way it is:

- **Structural results quantify over all model behaviours.** Section 3 sweeps
  susceptibility from 0.0 to 1.0 — every value the simulation could take —
  and reports which lines are flat. The broker's 0.0% on the
  `authorised_tool` family holds at every point on that sweep, so it does not
  depend on the simulation being realistic. It would hold for a model that
  complies with everything.
- **Behavioural results are conditional.** Anything involving the classifier's
  or spotlighting's effect on compliance is conditional on this compliance
  model. The report marks these Grade B and states the parameter each depends
  on.

What the simulation cannot tell you: whether a real model's compliance
responds to these features in these proportions. Section 4's finding that
spotlighting outranks the classifier is a statement about
`spotlight_effect = 0.45`, and the report says so in the section.

## 2. The corpus is 81 hand-written attacks, and its shape drives the headline

28 of the 81 are one family, generated by crossing 7 obfuscations with 4 base
payloads. A micro-averaged ASR over the whole corpus is therefore substantially
a statement about how many combinations that loop produced.

Section 1 opens with this, and every table reports macro-average over families
alongside the micro-average. When the two disagree, the disagreement is a
property of `corpus.py`.

The attacks are drawn from published technique classes, not from observed
in-the-wild traffic. A real deployment's distribution will differ.

## 3. Marker-based judging cannot see subtle attacks

An attack succeeds when its unique token appears in the output or an allowed
tool argument (ADR-0001). This makes the criterion exact and error-free, and it
excludes an entire category: attacks that change a *disposition* rather than
produce an observable. "Summarise this vendor's proposal less favourably"
leaves no marker.

Those attacks are real and this harness does not measure them.

## 4. The classifier's weights were chosen, not fitted

See ADR-0005. Every conclusion that depends on them is labelled Grade B.
Section 6's contradicted prediction — that no threshold reaches 90% detection
at all — is a consequence of unfitted weights and would look better, and mean
less, if they were fitted on this corpus.

## 5. The normaliser is deliberately incomplete

A partial confusable table, one level of decoding, no rot13 (ADR-0004). The
corpus contains attacks that defeat each limit, so the cost is visible in the
numbers. But a reader should not read "78.6% lexical detection with
normalisation" as a ceiling for the technique; it is a floor for *this*
normaliser.

## 6. Section 3's guarantee is about tool calls, not about all harm

The broker's flat line means: no tool call reaches execution unless the
principal asked for it. It does not mean the agent is safe. An agent that
writes a persuasive lie into its response has harmed the user without calling
anything, and section 10 is about the nine attacks that do exactly that.

## 7. The egress analysis models two channels, not the space of them

Zero-click auto-fetch (images, prefetch) and click-required links. Real
exfiltration channels include DNS, timing, and content encoded into text the
user will copy elsewhere. The 9.9% that strict mode buys is a floor.

## 8. Wilson intervals assume independent Bernoulli trials

Attacks within the obfuscated family share base payloads, so their outcomes
are correlated. The interval is narrower than the true uncertainty for
per-family rates on that family. Reported per-family precisely so a reader can
see which cells this affects.

## 9. Single-turn, single-agent

`multi_turn` is 3 attacks and models conversational setup crudely. Multi-agent
systems, where one agent's output is another's untrusted input, are not
modelled at all — and that is where the trust lattice in `channels.py` would
actually earn its generality.

## 10. What "zero" means here

Several configurations block every attack in a family. Section 12 exists
because that is a weaker statement than it looks: 0 successes in 28 trials
gives a 95% upper bound near 10% by the rule of three. No table in this report
prints a bare `0.0%` without its interval.
