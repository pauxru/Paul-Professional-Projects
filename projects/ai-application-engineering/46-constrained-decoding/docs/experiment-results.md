# Constrained decoding: measured results

Native core version `0.1.0`. No language model was used; the
model is a deterministic bigram, chosen because it is the largest model
family whose partition function over valid completions is computable.
Every table below is regenerated by `python -m schemafsm.experiments`.

distributions are computed in closed form, so these are not estimates.
`KL` is KL(masked || true conditional) in nats. The `doc` columns
marginalise over tokenisation, since one document can be produced by
several different token splits.

In every case the lookahead-reweighted decoder reproduced the exact

that the gap above is entirely caused by greedy local renormalisation.

## Where the two distributions disagree

| case | most likely under masking | most likely under true conditioning |
|---|---|---|
| enum-3 | `"red"` | `"red"` |
| bool-object | `{"ok":true}` | `{"ok":true}` |
| two-key-object | `{"b":false,"a":true}` | `{"b":false,"a":true}` |
| short-string | `"a"` | `""` **<- differs** |
| small-array | `[1]` | `[1]` |

When the modes differ, a constrained *greedy* decoder returns a document
the model considers less likely than another valid one. No amount of
validation catches this, because both documents are valid.

## Tokenisation ambiguity

A decoder samples token sequences; a user reads documents. The map is
many-to-one, so the probability of a document is a sum over its
tokenisations -- a sum a left-to-right decoder never computes.

| case | valid token sequences | distinct documents | max tokenisations of one document |
|---|---|---|---|
| enum-3 | 14 | 3 | 6 |
| bool-object | 23 | 2 | 14 |
| two-key-object | 64 | 8 | 8 |
| short-string | 18 | 7 | 5 |
| small-array | 35 | 6 | 8 |

## Retry versus constrain, as a function of how good the model is

`alpha` mixes a schema-aware bigram model with a random one. Token counts
are totals across all retry attempts, because that is what is paid for.

Schema: `bool-object`, vocabulary 13 tokens, 23 valid documents.

| alpha | single-shot validity | mean attempts | retry tokens | constrained tokens | retry cost | failures |
|---|---|---|---|---|---|---|
| 0.00 | 0.0% | 50.00 | 337.6 | 5.8 | n/a | 200 |
| 0.25 | 0.0% | 48.41 | 423.9 | 5.4 | n/a | 189 |
| 0.50 | 0.5% | 38.05 | 430.0 | 5.4 | n/a | 111 |
| 0.75 | 5.0% | 18.14 | 254.7 | 5.4 | n/a | 11 |
| 0.90 | 9.5% | 9.88 | 160.7 | 5.4 | n/a | 3 |
| 0.99 | 13.5% | 5.82 | 101.5 | 5.5 | 18.47x | 0 |
| 1.00 | 12.0% | 5.46 | 94.6 | 5.5 | 17.22x | 0 |

Read this as a decision rule, not a win: constrained decoding costs a
fixed mask per step, and retrying costs an unbounded number of passes.
Where the crossover sits depends entirely on the single-shot validity
rate, which is a property of the model and the prompt, not of the schema.

## Invariants checked while producing this document

- every enumerated document parses as JSON under the independent oracle
- every enumerated document is accepted by the automaton byte-wise
- the lookahead-reweighted decoder equals the exact conditional to 1e-12
- masked and exact distributions each sum to 1 to within 1e-12
