# Forecast Accuracy

## Method
This result is from the deterministic local synthetic dataset generated by `SyntheticFinOpsData` (2024-10-01 to 2026-08-31). For each completed month after two history months, the forecaster received the first 14 daily observations and predicted month-end total. MAPE is the mean of `abs(prediction - actual) / actual`.

Command executed on 2026-09-03:

```powershell
dotnet test tests\CloudCostObservability.UnitTests\CloudCostObservability.UnitTests.csproj -c Release `
  --filter "FullyQualifiedName~SyntheticDataset_BacktestsForecastAndEvaluatesKnownInjectedAnomalies" `
  --logger "console;verbosity=detailed"
```

## Measured result

| Method | Months evaluated | MAPE |
|---|---:|---:|
| Simple run-rate | 21 | **0.93%** |
| Seasonal-aware day-of-week decomposition | 21 | **0.63%** |
| Linear regression | 21 | **0.89%** |

The default is **seasonal-aware** because it had the smallest measured MAPE, not because it was assumed to be more sophisticated. The API returns all three forecasts and a confidence interval, preserving the ability to compare methods.

## Interpretation
The synthetic series intentionally contains weekday/weekend differences, recurring month-end workload, gradual growth, and injected cost changes. The lower seasonal-aware error is consistent with the data generating process. This is a repeatable local measurement, not a claim about accuracy on a real organisation's cloud spend.

## Guardrails
MAPE is not meaningful near a zero actual; those periods are omitted by the backtest. A structural break can invalidate historical fit, so forecast outputs are paired with confidence bounds and anomaly/change-point signals. In an enterprise deployment, forecast selection would be recalculated by scope (team/service/subscription) and monitored over rolling validation windows.
